## 1. Context

Spec 007 stores, for the current sheet of a match, at most one summary per input fingerprint: a deterministic template, or one text generated by Claude Haiku 5.5. Every stored row is `PorVerificar` or `Borrador`, and nothing is published. The schema check of Spec 007 R-24 only checks the shape of the output. The 2026-11-12 measurement showed two texts (adaptive thinking) that use only names and numbers of the input and still assert facts the input does not contain: an order of goals ("descontó", "se adelantó", "respondió") and "sin incidencias oficiales". It also showed that the wording about cards varies between runs, and that "no hubo tarjetas informadas" cannot be told apart from "cards were not reported" when cards were reported and are none. This Spec adds the deterministic verifier that the course format and ADR-12 promise, rejects texts before they are stored, and defines publication as a pure function of the current sheet.

## 2. Goal

A model text is stored only if the deterministic verifier approves it against the exact canonical input that produced it; a summary is shown for a match if and only if its fingerprint is the current one, it is not a draft, and the current verifier approves it against the current input. A rejection costs at most the existing cap of three billed calls per fingerprint and is recorded on the call row, with no schema change.

## 3. Requirements (EARS)

### 3.1 The verifier (pure code in `GoalFlow.Application.IA.Verificacion`, no I/O)

| ID | Requirement |
| --- | --- |
| R-01 | `VerificadorDeResumen.Verificar(string texto, EntradaCanonica entrada)` shall return a `ResultadoDeVerificacion` with `Aprobado` and the ordered, distinct list of rule identifiers that failed (`V1` to `V8`, in that order). It is approved if and only if the list is empty. The result depends only on its two arguments: no clock, culture, configuration, randomness or I/O. The constant `VersionDelVerificador` is `v1`; any change of R-02 to R-11 b after its first release changes it. |
| R-02 | **Masked values.** Before anything else, the text and every value of M are normalized to Unicode NFC. The set M is: `torneo`, `local`, `visitante`, every `jugador` of `goles`, `autogoles` and `tarjetas`, the `estado` value, and the literal `W.O.`. Every occurrence of a value of M in the text shall be replaced, before any rule runs, by one placeholder token that is never capitalized, never a number, never in a word list and never a sentence terminator. Matching compares the invariant-culture lowercase form of both strings (accents are significant) and requires that the character before and after the occurrence, if any, is neither a letter nor a digit. At each position, values are tried from longest to shortest (ordinal order for equal lengths), scanning left to right; matches do not overlap. |
| R-03 | **Sentences and tokens.** After masking, sentences are the maximal runs between `.`, `!`, `?` and `;`. Tokens are the maximal runs of letters (`char.IsLetter`) and the maximal runs of digits (`char.IsDigit`), plus the placeholders; every other character separates tokens. The **folded** form of a token is its invariant lowercase form with every non-spacing mark removed after Unicode NFD decomposition (`además` → `ademas`). A token **starts** a sentence if it is the first token of its sentence. A word-list entry ending in `*` matches any folded token that starts with it; any other entry matches a folded token exactly; a multi-word entry matches consecutive tokens of one sentence. |
| R-04 | **The number set A** is every integer of the canonical input (`fase`, `jornada`, both values of `marcador`, `oficial` and `golesSinAutor`, and every `cantidad`), plus `marcador.local + marcador.visitante` when `marcador` is present, plus the sum of the `cantidad` of every card. |
| R-05 | **V1, name.** A letter token whose first character is uppercase fails V1 if it does not start its sentence, or if it starts its sentence and its folded form is not in INICIOS = {`en`, `el`, `la`, `los`, `las`, `un`, `una`, `por`, `para`, `con`, `sin`, `no`, `ni`, `se`, `ademas`, `tambien`, `ambos`, `ambas`, `tras`, `hubo`, `fue`, `goles`, `tarjetas`, `detalle`}. |
| R-06 | **V2, number.** A digit token fails V2 if it has more than 6 digits or its value is not in A. A letter token whose folded form is in NUMEROS fails V2 if its value is not in A. NUMEROS = `cero` 0, `uno` 1, `dos` 2, `tres` 3, `cuatro` 4, `cinco` 5, `seis` 6, `siete` 7, `ocho` 8, `nueve` 9, `diez` 10, `once` 11, `doce` 12, `trece` 13, `catorce` 14, `quince` 15, `dieciseis` 16, `diecisiete` 17, `dieciocho` 18, `diecinueve` 19, `veinte` 20, `doblete` 2, `triplete` 3. `un` and `una` are articles and never numbers (C-04). |
| R-07 | **V3, chronology.** The text fails V3 if any token or sequence matches CRONOLOGIA = {`minut*`, `tiempo`, `tiempos`, `mitad*`, `descanso*`, `entretiempo*`, `inicio`, `comienzo`, `finalmente`, `al final`, `sobre el final`, `abrio`, `cerro`, `adelant*`, `remont*`, `descont*`, `respondi*`, `ampli*`, `ventaja*`, `sentenci*`, `luego`, `despues`, `posterior*`, `antes`, `enseguida`, `tempran*`, `agonic*`, `primer gol`, `segundo gol`, `ultimo gol`}. The canonical input has no chronology (Spec 007 R-08), so any of them asserts a fact the input cannot support. |
| R-08 | **V4, incidents.** The text fails V4 if any token or sequence matches INCIDENCIAS = {`arbitr*`, `juez`, `jueces`, `incidenc*`, `polemic*`, `protest*`, `expuls*`, `penal*`, `penalty`, `corner*`, `tiro libre`, `fuera de juego`, `lesion*`, `asist*`}. |
| R-09 | **V5, setting.** The text fails V5 if any token matches AMBIENTE = {`clima`, `lluvi*`, `cancha*`, `estadio*`, `hinch*`, `aficion*`, `publico`}. |
| R-10 | **V6, card reporting.** Let a card sentence be a sentence with a token matching `tarjeta*`, and INFORMACION = {`informad*`, `informaron`, `informo`, `informacion`, `reportad*`}. If `tarjetasInformadas` is `false` or `null`, then every card sentence shall contain a token of INFORMACION, or the text fails V6 (the text may say that cards were not reported, never that there were none). If `tarjetasInformadas` is `true` and the input has no card, then a card sentence that contains a token of INFORMACION fails V6 ("no hubo tarjetas informadas" reads both as "none" and as "not reported"; C-06). If `tarjetasInformadas` is `true` and the input has cards, then a card sentence that contains a token of NEGACION = {`no`, `ni`, `sin`, `ninguna`, `ningun`, `ninguno`} and no placeholder fails V6 (it denies cards that were shown). |
| R-11 | **V7, colors.** A token matching `amarill*`, `roj*` or `azul*` fails V7 if the input has no card of that color (`Amarilla`, `Roja`, `Azul`). |
| R-11 b | **V8, characters.** Every character of the NFC text that is outside a masked occurrence and whose Unicode category is `NonSpacingMark`, `SpacingCombiningMark`, `EnclosingMark`, `Format`, `PrivateUse`, `Surrogate` or `OtherNotAssigned` fails V8. Such a character splits a token and could hide a listed word (`des` + U+00AD + `contó`) or imitate a placeholder. Spanish text in NFC needs none of them; characters inside a name are masked first, so a name may contain them (C-15). |
| R-12 | **Correct by construction.** For every canonical input accepted by Spec 007, the verifier shall approve the `Jugado` template, the `Adjudicado` template and the extended draft of Spec 007 R-11. The compact draft is not covered: its fixed sentence about omitted detail is never published (C-08). |

### 3.2 The consumer `ia.resumen-partido` (amends Spec 007 R-21 and R-22)

| ID | Requirement |
| --- | --- |
| R-13 | When a generation succeeds and its output is valid under Spec 007 R-24, the consumer shall run R-01 on the trimmed text and the canonical input of the delivery, **before** any write. If approved, Spec 007 R-22 applies unchanged. |
| R-14 | If the verifier rejects the text, then the consumer shall reconcile the call with the reported usage (Spec 007 R-23) and the outcome code `verificacion_rechazada:{VersionDelVerificador}:{rules}` (for example `verificacion_rechazada:v1:V3,V4`; at most 49 characters, 56 with the overrun suffix of Spec 007, below the 64 of the column), insert nothing, log a `Warning` and throw a retryable failure. The next attempt makes the next numbered call; the cap of three billed calls per (match, fingerprint) of Spec 007 R-17 counts rejected calls like any other, and the attempt that finds the cap stored stores the `limite_de_llamadas` draft (C-02). |
| R-15 | The retry shall send exactly the same request (same system text, same canonical input, same `version_prompt` `a01-v1`): no feedback about the rejection reaches the model (C-03). |
| R-16 | In addition to the retryable-failure `Warning` that every retryable outcome already writes (Spec 007), the rejection log shall carry, through `ILogger<T>` only: tenant, match id, version, the first 12 characters of the fingerprint, call number, delivery attempt, `VersionDelVerificador` and the rule identifiers. It shall never carry the text, a name, the input or a matched word (Spec 007 R-27). |

## 4. Non-functional constraints

- **Bounded and deterministic (owner's condition for C-01).** The text is at most 900 characters (Spec 007 R-24) and the canonical input at most 16,384 bytes (ADR-12 §2.10). The verifier makes one masking pass that tries every value of M at each position, then one linear pass per rule: no regular expressions and no backtracking (R-21). Results are identical under any current culture (T-09 runs under `tr-TR`).
- **No paid call.** Every test of this Spec uses the corpus, generated sheets or the fake generator. Amplification with the verifier on is measured with real calls only when the owner enables IA with real data (metric 3), never in CI.
- **Prompt unchanged.** `a01-v1` stays (C-03, C-05). A new prompt requires its own Spec change and a paid run authorized by the owner.
