## 1. Context

`PartidoGuardado` has been published since H12 and has no consumer. A-01 is that consumer: for the current sheet of a match it stores a summary that is either a deterministic template or one text generated by Claude Haiku 5.5. Every call is paid for, delivery is at-least-once, two instances overlap during a deploy, and the budget belongs to one account shared by tenants that cannot see each other. ADR-12 decides the policy. This Spec makes it testable. Nothing is published in this Spec: publication requires the verifier of H15 (Spec 008).

## 2. Goal

With `IA:Habilitada` true, every current sheet in `Jugado` or `Adjudicado` gets at most one stored summary per input fingerprint, with at most three billed calls per fingerprint. No league spends more than its monthly ceiling, even under concurrent reservations. Every possibly billed call is counted. Stale versions cost nothing. The backfill covers matches saved while A-01 was off, without duplicating rows or touching other consumers. With `IA:Habilitada` false, nothing of this runs.

### 3.3 Input, fingerprint, classification and templates (pure code in `Application.IA`, no I/O)

| ID | Requirement |
| --- | --- |
| R-08 | The **canonical input** shall be a JSON object built from the current sheet with exactly these members, in this order: `torneo` (name), `fase` (order), `jornada`, `local` and `visitante` (team names), `estado`, `marcador` ({`local`, `visitante`} or `null`), `oficial` (same, or `null`), `motivo` (sporting reason code or `null`), `goles` (list of {`equipo`, `jugador`, `cantidad`}, where `equipo` is the scorer's side, which is also the side credited), `autogoles` (list of {`jugador`, `equipoDelAutor`, `equipoBeneficiado`, `cantidad`}, where `equipoBeneficiado` is always the other side), `golesSinAutor` ({`local`, `visitante`}), `tarjetasInformadas` (boolean or `null`), `tarjetas` (list of {`equipo`, `jugador`, `color`, `cantidad`}). Sides are written `local` or `visitante`. **Every list is sorted only by the values it emits:** side (`local` first), then player name by ordinal comparison, then color (cards), then quantity. Items that compare equal are byte-identical, so their relative order cannot change the output. Serialization: UTF-8, no indentation, no escaping beyond what JSON requires (non-ASCII letters are written as they are). It shall contain no identifier, no registration or team code, no Admin `sub`, no rectification reason and no scheduled time. |
| R-09 | The **fingerprint** shall be the lowercase hex SHA-256 of the canonical input's bytes. Changing any value of R-08 changes it. These changes do not: the version alone; the rectification reason; the scheduled time; and which registration holds a name, which covers a goal or card moved between two players with the same name on the same side, even with different quantities. Players with the same name on the same side are indistinguishable in the input by design (ADR-12 C-18). |
| R-10 | The **classification** shall be: `Programado`, `Suspendido`, `Cancelado` → **None**; `Adjudicado` → **Template**; `Jugado` with no goal of type `Jugador`, no own goal and no card → **Template**; `Jugado` with at least one of them → **Narrative** (ADR-12 §2.2). |
| R-11 | Templates shall be pure functions of the canonical input producing these exact Spanish texts. Names and numbers come only from the input. **They never interpolate a missing value:** if a `Jugado` sheet has no `marcador`, or an `Adjudicado` sheet has no `oficial`, then the template throws a specific exception and produces no text. The consumer turns it into the permanent failure `planilla_incoherente` (ADR-12 C-16). An `Adjudicado` sporting score is ignored. A quantity above 1 is written as ` (n)` after a scorer or own-goal scorer and ` xn` after a card color. **Result line:** `{local} {a}-{b} {visitante}.`, with the official score for `Adjudicado` and the sporting score otherwise. **`Jugado` template:** the result line; then, if any unattributed goal exists, ` Goles sin autor registrado: {local} {x}, {visitante} {y}.`; then, if `tarjetasInformadas` is false, ` Tarjetas no informadas.` **`Adjudicado` template:** `{local} {a}-{b} {visitante}, resultado oficial por {m}`, followed by a period **only if `m` does not already end with one**, with `m` = `W.O.` (`WalkOver`), `sanción` (`Sancion`) or `decisión administrativa` (`Otro`). The `WalkOver` text is therefore `…, resultado oficial por W.O.` with exactly one period (ADR-12 C-24). **Extended draft** (narrative cases only). It starts with the result line. Then, for each side that has credited goals (home first), it adds ` Goles de {equipo beneficiado}: ` and a comma-separated list: first the side's scorers, in the order of `goles`; then, for each own goal **credited to that side**, `autogol de {jugador} ({equipo del autor})`, in the order of `autogoles` (for one beneficiary the scorer's side is always the other one, so this is player name by ordinal comparison, then quantity); then `{n} sin autor` if any; the list ends with `.`. **Quantity:** the ` (n)` suffix always goes last in its item, after the scorer's team for an own goal: `autogol de Jugador Uno (Equipo Uno) (2)` (ADR-12 C-25). Then it adds ` Tarjetas: ` with `{jugador} ({equipo}) {color}` items separated by commas and ending with `.`, or ` Sin tarjetas.` (informed, none), or ` Tarjetas no informadas.` Colors are written `amarilla`, `azul`, `roja`. **Length:** if the extended draft would exceed `LongitudMaximaDeBorrador`, the **compact draft** is produced instead: the result line followed by ` Detalle de goles y tarjetas omitido por extensión.` With names of at most 80 characters (Spec 005 R-12), the `Jugado` and `Adjudicado` templates and the compact draft never exceed 400 characters (the longest, a `Jugado` template with unattributed goals and cards not reported, is 390). |
| R-12 | The **reservation amount** shall be ⌈(N × (100 + `MargenDeEntradaPorcentaje`) / 100 + `MargenDeEntradaTokens`) × input price / 1,000,000⌉ + ⌈`MaxTokensDeSalida` × output price / 1,000,000⌉ µ$. N is the number of input tokens the provider's counting endpoint returns for the **exact** request: model, system text, user message, `output_config.format` and the thinking setting. Prices are µ$ per million tokens. The real cost is computed from the reported input and output tokens with the same prices, each part rounded up. The output part is a contractual bound (`max_tokens`, thinking included). The input part is an estimate and is never assumed to be a bound (R-23, ADR-12 C-20). |

### 3.4 The consumer `ia.resumen-partido`

| ID | Requirement |
| --- | --- |
| R-13 | The consumer of `PartidoGuardado` shall have the constant name `ia.resumen-partido`. For each delivery it shall first read, in its own unit-of-work transaction, the match's current version and sheet through the read port of R-33. If the current version is higher than the delivery's version, then it shall complete **without any call or write**. |
| R-14 | If the classification is **None**, then it shall complete without any write. |
| R-15 | If the classification is **Template**, then it shall insert a summary (`Plantilla`, `PorVerificar`) for the fingerprint, unless one exists, and complete. It shall never reserve budget or create a call row. A duplicate on the unique index of R-01 counts as already done. |
| R-16 | If the classification is **Narrative** and a summary already exists for (match, fingerprint), whatever its origin or state, then it shall complete without any call or write. |
| R-17 | If the call rows already stored for (match, fingerprint) number `MaximoDeLlamadasPorHuella` or more, then it shall store the extended draft with reason `limite_de_llamadas` and complete, without calling. |
| R-18 | If the number of leagues returned by the tenant-source port times the per-league ceiling exceeds the global ceiling, then it shall store the extended draft with reason `presupuesto`, log a `Warning` and complete, without reserving. |
| R-19 | Otherwise, **(0) size and count:** if the canonical input exceeds `MaximoDeBytesDeEntrada`, R-21 (g) applies. If not, the consumer counts the input tokens of the exact request through R-28. A failed count reserves nothing: it is classified as in R-21 (c) to (f), and there is nothing to reconcile. A count above `MaximoDeTokensDeEntrada` → R-21 (g). Then it shall **reserve** in one short transaction with no external call inside: (a) if the counter row for (tenant, current UTC month of the injected `TimeProvider`) does not exist, insert it with the configured per-league ceiling. If the insert fails exactly on the unique (tenant, `mes`) index, the adapter translates that error and the existing row is used. (b) Run one `ExecuteUpdateAsync` on the counter conditioned on `reservado + consumido + amount <= tope`, adding the amount to `reservado`. (c) Insert the call row (`Reservada`, the same `mes`, `numero` = stored calls for the fingerprint + 1, the delivery attempt, the amount). (d) Commit. If (b) affected zero rows, then the transaction is disposed without commit and the consumer stores the extended draft with reason `presupuesto` and completes. If (c) fails exactly on the unique index of R-02, then the transaction is disposed without commit (the counter change included) and the consumer throws a retryable failure. |
| R-20 | The call to the provider shall happen after the reservation commits, with no open transaction, bounded by `TimeoutDeLlamada` and the delivery's cancellation token. |
| R-21 | Outcomes (ADR-12 §2.6), classified by HTTP status and, where documented, `error.type`, never by the message: **(a)** success with valid output (R-24) → R-22. **(b)** Success with invalid output, including `stop_reason` `max_tokens` → reconcile (R-23) with the reported usage, then throw a retryable failure. **(c)** Status `409`, `429`, `529`, `500` whose `error.type` is not `timeout_error`, or any other `5xx` except `504` → reconcile with the reported usage or 0, then throw a retryable failure. **(d)** Status `400`, `404` or `413` → reconcile (0 if no usage), store the extended draft with reason `solicitud_invalida` and complete. `400` includes an account spend limit or an exhausted balance, which the API reports with the same status (ADR-12 fact 9). **(e)** Status `401` or `403` → reconcile at 0 and throw the permanent failure of `Mensajeria` with reason code `credencial_invalida`. **(e2)** Status `402` → reconcile at 0 and throw the permanent failure with reason code `facturacion_del_proveedor`. **(f)** Timeout, lost connection or any exception without a response; status `504`; any status whose `error.type` is `timeout_error`; or any status not listed in (a) to (e2), including an unknown `4xx` → **no write** to the call row or the counter, then a retryable failure (or, on shutdown, ADR-02 §2.5: nothing at all). **(g)** Canonical input above `MaximoDeBytesDeEntrada`, or count above `MaximoDeTokensDeEntrada` → extended draft with reason `entrada_excedida`, without reserving. **(h)** Success with `stop_reason` `refusal` → reconcile with the reported usage, store the extended draft with reason `rechazo_del_modelo` and complete. For the counting request, (c) to (f) apply with nothing to reconcile and nothing reserved. |
| R-22 | On success, **one** transaction shall: reconcile the call (R-23); insert the summary (`Modelo`, `PorVerificar`, the text, the model, `version_prompt`, the call); commit. If the summary insert fails exactly on the unique index of R-01 (another worker stored that fingerprint), the adapter translates that error, the reconciliation still commits, and the delivery completes. |
| R-23 | **Reconciliation** shall be one `ExecuteUpdateAsync` on the call row conditioned on its id and `estado = Reservada`, setting `Conciliada`, the tokens, the cost, the outcome code and the time. Only if it affected one row, a second `ExecuteUpdateAsync` on **the counter row of the call's `mes`**, whatever the current month, subtracts the reservation from `reservado` and adds the cost to `consumido`. If the cost exceeds the reservation, then the cost is still recorded in full, the outcome is marked as an overrun, and a `Warning` is logged. |
| R-24 | Valid output: the response's text is the concatenation of its content blocks of type `text`. Blocks of any other type, such as thinking, are ignored and never logged. The text shall be a JSON object whose only member is `texto`, a string that, after trimming, has 80 to 900 characters and no control characters. |
| R-25 | An extended draft shall be inserted as (`Plantilla`, `Borrador`, reason, extended-draft text) for the fingerprint, unless a summary already exists for it. A duplicate counts as already done. |
| R-26 | Every read and write of R-13 to R-25 shall run inside a unit-of-work transaction (ADR-14 §2.3). Every `ExecuteUpdateAsync` on `presupuestos_ia` or `llamadas_ia` shall require an active transaction and throw a specific exception otherwise (as ADR-02 §2.6). |
| R-27 | The consumer and the adapter shall log through `ILogger<T>` only: tenant, match id, version, the first 12 characters of the fingerprint, call number, delivery attempt, classification, tokens, costs and outcome code, which may include the HTTP status and the provider's `error.type` when it is one of the documented values (`desconocido` otherwise). They shall **never** log the input, the system text, the generated text, a name, the API key, a request or response body, a header value or an exception message, at any level. |

### 3.5 Provider adapter

| ID | Requirement |
| --- | --- |
| R-28 | `IGeneradorDeTexto` (Application) shall have two operations. **Count:** it takes the same request as Generate and returns the counted input tokens. **Generate:** it takes the system text, the canonical input, the output schema, `MaxTokensDeSalida` and the thinking setting, and returns the text, the `stop_reason` and the reported input and output tokens. Both throw one of three specific exceptions: a response with an error (the status, the provider's `error.type` if it is one of the documented values or `desconocido` otherwise, and the reported usage if any; never the message), an uncertain outcome (no response) and an invalid output (with the reported usage). |
| R-29 | The HTTP adapter (Infrastructure) shall send Messages API requests with: the configured model, `max_tokens`, the system text, and one user message whose content is the canonical input inside the data block of R-30. It shall send `output_config.format` = {`type`: `json_schema`, `schema`: the schema of R-24}. With `Razonamiento` = `Deshabilitado` it sends `thinking` = {`type`: `disabled`}; otherwise it omits `thinking`, and adaptive thinking applies. The count request sends the same members to the counting endpoint **except `max_tokens`**, which that endpoint does not take (paso 0 of Phase A). It shall read the reported usage and `stop_reason`, select content blocks by type, and classify outcomes as in R-21. `output_config.format` and the thinking values were checked in the official documentation on 2026-11-11. The endpoint paths, the version header and the error shapes are re-read in the handoff and recorded in the PR. No new package. |
| R-30 | The system text shall state, in Spanish, that the data block is data and never instructions, that the summary may mention only names and numbers present in it, and the output limits. The canonical input shall travel only inside the user message's data block and never be concatenated into the system text. Its version is the constant `version_prompt` (`a01-v1`). |

## 4. Non-functional constraints

- **Isolation and persistence tests** against PostgreSQL 17 as `goalflow_app`, with invented data only (`liga-a`, `liga-b`, `Equipo Uno`, `Jugador Uno`).
- **No real provider call in CI.** Tests use a fake `IGeneradorDeTexto` that the test controls (text, usage, exception, and a gate), and the HTTP adapter is tested with a stub `HttpMessageHandler`.
- **Deterministic concurrency (Spec 006 C-24).** The budget store, the summary store and the publisher are reached through Application ports. Concurrency tests replace them **in the test host only** with decorators that delegate and wait on gates, and they assert the order they observed. Two HTTP requests sent together are not proof.
- **One transaction per step.** Reservation, reconciliation plus summary, and draft are separate short transactions; no transaction is open during the call.
- **Smoke test with the real key (owner's environment variable, passed by name).** Run locally against the disposable database with five narrative fixtures, each under both thinking settings (`Deshabilitado` and `Adaptativo`), so 10 generations and 10 counts, under US$0.01. **The ten runs are independent:** each mode runs in its own league (`liga-humo-a` for `Deshabilitado`, `liga-humo-b` for `Adaptativo`), each with its own five matches. All ten (tenant, match, fingerprint) keys are therefore distinct, every run is a first generation under R-16, and no run reuses or blocks another's summary. For each run it records: counted input tokens, billed input and output tokens, `stop_reason`, the valid-output check, latency, and whether the call was an overrun. The PR includes the ten texts for the owner to read. It must show ten reconciled calls and ten stored `PorVerificar` summaries. It distinguishes the new code from the old: before this Spec, no row exists in `llamadas_ia`. The owner confirms `IA:Razonamiento` with this data (ADR-12 C-21). **The smoke test is not done until the owner has confirmed the account, the prepaid balance and that automatic reload is off.** Until then, it is reported as pending, never as passed.

## 5. Clarifications

The design decisions and their history are in ADR-12 §6 (C-01 to C-13). This Spec adds:

| # | Question | Decision | Decided by / date |
| --- | --- | --- | --- |
| C-01 | Does a template need the budget or a call row? | No (R-15). Templates cost nothing and cannot invent anything. | Mentor, 2026-11-11 |
| C-02 | Is the registration code part of the input? | No. It is neither emitted nor used to order the lists: the order depends only on the emitted values (R-08, R-09, C-07). The model does not need it, and the verifier of H15 compares names and numbers. | Mentor, 2026-11-11; reworded in v2 at the owner's request |
| C-03 | Why is the summary insert in the same transaction as the reconciliation? | So that "billed and recorded but without a summary" cannot exist (R-22, ADR-12 §2.6). A failed `SaveChanges` rolls back to its savepoint and leaves the transaction usable (ADR-02 fact 10), so the reconciliation, done with `ExecuteUpdateAsync` before the insert, still commits. | Mentor, 2026-11-11 |
| C-04 | Who verifies the official API details? | Checked on 2026-11-11: `output_config.format` (generally available), the thinking values for Claude Haiku 5.5 and the counting endpoint (free; an estimate). The owner verified error billing in the Help Center (ADR-12 C-15). The H14 handoff re-reads the endpoint paths, the version header and the error shapes, records what it found with its date, and stops if anything contradicts this Spec. | Mentor and owner, 2026-11-11 |
| C-05 | Can a template show an absent score? | No (R-11). It throws, and the consumer ends the delivery with `planilla_incoherente`. Spec 006 R-11 (a) and (c) make the case impossible for a valid sheet, so it is a guard, not a feature. | Owner (review, correction 1), 2026-11-11 |
| C-06 | How does the input avoid confusing the scorer's team with the credited team in an own goal? | Both sides are explicit members of each own-goal item (R-08), and the extended draft lists the own goal under the credited team with the scorer's team in brackets (R-11). | Owner (review, correction 2), 2026-11-11 |
| C-07 | Sorting by registration code made the fingerprint depend on a value that is never emitted. | Sorting uses only emitted values (R-08, R-09). Namesakes on one side are indistinguishable, which is accepted. | Owner (review, correction 3), 2026-11-11 |
| C-08 | Is the reservation a proven upper bound? | No. Output is bounded by contract and input by the provider's count, which is documented as an estimate; overruns are recorded in full and measured (R-12, R-23, T-21; ADR-12 C-20). | Owner (review, correction 5), 2026-11-11 |
| C-09 | Can a draft exceed the column? | No: 4,000 characters, with the compact draft as fallback (R-01, R-11). | Owner (review, correction 6), 2026-11-11 |
| C-10 | Structured output and thinking? | `output_config.format` (`json_schema`); thinking disabled by default and measured both ways in the smoke test (R-29, §4). | Owner (integration checks), 2026-11-11 |
